# 美团外卖营业数据抓取（第一表）

用户指定入口：美团外卖品牌后台 → 经营罗盘 → 报表下载 → 勾选字段 → 下载数据。

第一表共 15 个字段，按 2026-10-06 用户截图固定：日期、门店名称、门店 id、省份、门店所在城市、区县市、营业收入、优惠前总额、有效订单、曝光人数、入店人数、入店转化率、下单转化率、下单人数、综合体验分。不选择曝光次数或其他附加指标。

## 当前状态

已完成真实登录和第一表下载。现场流程为创建导出任务后点击“前往下载”，在下载列表找到该任务并下载 CSV；不是点击“下载数据”立即获取文件。2026-10-05 原件的字段、日期、门店唯一性和金额已通过独立 Python CSV 核对及项目解析器核对，原件与私有校验回执归档至 `_handover/meituan-delivery-20261006/`。

新增字段契约、只读文件校验和任务下载模块，并接入独立浏览器宿主 `daemon.js`、完整任务执行器 `runner.js`、CLI 与计划入口。执行器自动导航、填写日期、设置全部门店/全部业务/按天和 15 个字段，提交导出，按准确任务名下载归档，再调用中控 HMAC 导入接口；最后回读数据库逐字段验证。任务状态保存于独立平台目录，重启后恢复原任务，不重复提交导出；同日期同原件重复导入只核验已有批次。

后台美团外卖分析页面新增“美团外卖营业表明细”，原样展示 15 字段及门店归属、机器人核验状态。单店单日转化率显示平台原值，汇总分析仍按人数加权计算。正式导入、同源幂等、缺失保留、数据库变更检测、HMAC 及北京时间计划的离线测试通过；云端机器人真实闭环测试另留私有验收记录，不将代码部署本身等同于验收。

真实测试默认先取昨日一个完整业务日，全部门店。若现场提供不同的日期、门店范围或文件格式，先读取界面和原件证据再调整，不猜测站内接口或选择器。第一表完成后再按用户提供的步骤开发第二、第三表。

## 文件校验

- 单工作表和唯一表头，字段完整且无重复、无多选；CSV 保留原始日期文本，防止时区自动转换。
- 明细日期必须在请求区间内，每个日期有数据；同一天同门店只能有一条记录。
- 门店 ID 以字符串保留；不接受已经失去整数精度的 Excel 数字 ID。传入已核验的平台门店 ID 时检查未知门店和缺门店。
- 金额按分汇总；非法数值不能默认为零。订单和人数必须为非负整数；评分、转化率检查范围，平台的缺失标记保持原样。
- 实际原件为 GBK CSV，日期为 `YYYYMMDD` 文本；数值转化率为 0–1 小数，带百分号文本为 0–100。原值保留，不将小数误当百分数。
- 空金额、空订单保持源空值，并返回各字段缺失数和 `totals_complete`。金额和订单汇总仅累加非空值，不能以汇总通过认定缺失值就是零。
- 返回原文件 SHA256、条数、门店数、日期集合和金额汇总，不修改数据库。

现有中控 `lib/business-analytics.js` 已有美团经营日报导入分支，按美团门店 ID 和日期去重，写入 `meituan_delivery_operation_records`。后续自动导入需由采集器调用中控 API，并核对类型 `operating`、门店覆盖、日期及回执。营业数据表的营业收入不等于结算真实到账，真实到账须由后续第三表提供。

机器人在入库前强制核对平台 ID 绑定，未知或缺少门店时停止；不通过模糊名称自动归属。现场缺少的绑定按真实原件与唯一对应的既有门店主档核验后，由有备份的发布迁移补齐。

账号密码不写入代码、文档或测试；登录态和真实下载原件保存在私有运行目录。当前收银报表与记账本定时器不因本次第一表开发改变。
