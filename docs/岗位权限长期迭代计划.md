# 岗位权限长期迭代计划

## 目标

采用单一的“岗位”体系：岗位就是成员的系统角色和权限集合，例如系统管理员、门店店长、运营专员、财务人员。人员只分配一个岗位；岗位变更后，已分配人员实时继承新权限。

## 当前节点（2026-09-16）

- 已建立岗位配置表，可新增、编辑、删除自定义岗位。
- 已内置系统管理员、运营专员、门店店长、财务人员四个基础岗位。
- 系统管理新增“岗位设置”路由，支持按模块勾选权限。
- 人员管理可为每个后台账号分配或取消岗位，并显示当前岗位。
- 岗位配置仅允许管理员维护；系统预置岗位可编辑，不能删除。

## 重大更新必做清单

每一次新增或重大调整业务功能时，必须同步检查并更新本文件中的以下事项：

1. 为新页面、接口和关键动作定义清晰的权限编码。
2. 在岗位设置界面补充对应权限项及中文说明，并与左侧导航的分类、名称、排序同步。
3. 前端导航、页面按钮、数据范围按权限做可见性和只读处理。
4. 后端接口必须做真实权限校验，不能只依赖前端隐藏按钮。
5. 使用管理员和最小权限岗位各验证一次：可访问、不可访问、接口绕过均应符合预期。
6. 记录本次新增权限、数据影响范围及兼容/迁移方案。

## 后续里程碑

### M2：页面与操作权限落地

- 根据岗位权限隐藏或禁用导航、查询、导入、编辑、删除等操作。
- 对现有系统管理、数据导入、门店、菜品、成本、记账、人事、协同模块逐项补齐权限。

### M3：后端强制校验与审计

- 统一权限中间件，所有写入接口和敏感读取接口服务端拦截。
- 记录岗位变更、人员授权变更、关键操作日志，并支持按人员追溯。

### M4：数据范围权限

- 支持品牌、区域、门店的数据范围。
- 同一岗位可按门店范围派生不同授权，适用于店长、督导和区域负责人。

### M5：审批与临时授权

- 高风险权限申请、审批、到期回收。
- 临时授权自动失效，支持异常授权提醒。
