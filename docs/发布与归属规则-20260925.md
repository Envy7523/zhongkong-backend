## 修改与发布

1. 开发只在 Git 分支和隔离环境进行。提交前检查差异、敏感信息、单元测试、前端构建，并用只读方式对照云端源代码，确认没有别的 AI 未归档的改动。
2. 推送开发分支。发布只使用明确提交号，建立新的云端发布目录；不要在正在运行的目录里直接编辑源代码。
3. 云端数据库、配置、上传目录与旧工作目录共享；切换前停服务并备份数据库，切换后验证进程工作目录、HTTP、定时器与核心配置。保留前一发布目录用于回退。
4. 若有人直接改动云端源码，先停止发布，读取差异并把需要保留的改动移入 Git；不得用本地版本覆盖未知变更。
5. “发布完成”不等于“业务闭环完成”。每个平台、每份报表单独验收采集、导入、对账、展示与推送。
