# 报表同步与日报发送解耦（2026-09-27）

## 职责边界

- 收银系统机器人仅负责各报表的查询、单次导出、下载观察、文件校验和经中控导入。它不决定日报内容、不持有日报机器人路由，也不发送日报。
- 中控读取云端数据库已有数据，使用已审批的收银系统单张全门店总览模板、绑定的企微机器人和既有发送闸门，自行在日报计划时间生成并发送。B「品项销售明细」及 C「门店收支统计」的导入不自动加入该日报，更不会单独发群消息。
- 同步计划以“平台 + 报表”为单位；日报计划独立。新增平台时须各自注册报表类型、解析和导入验证，不能把“导入成功”自动等同“可纳入日报”。

## 当前计划与入口

| 报表 | 计划来源 | 当前时间（北京时间） | 用途 |
| --- | --- | --- | --- |
| 综合营业统计 A | 既有 `schedule_config.sync_*` | 01:05 | 采集与导入 |
| 品项销售明细 B | `report_sync_plans` | 03:20 | 采集与导入 |
| 门店收支统计 C | `report_sync_plans` | 04:40 | 采集与导入 |
| 收银日报 | 既有 `schedule_config.report_*` | 09:00 | 中控汇总和发送 |

中控界面：数据导入 → 收银系统 · 自动导报表 →「各报表同步计划」；日报计划在企业设置 → 自动报表与日报，日报预览及机器人绑定仍在收银系统自动导报表的独立页签。保存时间只影响未来运行，不补跑旧业务日。

同一美团管家采集站点，启用的 A/B/C 时间必须至少间隔 60 分钟（含跨午夜）；A 旧计划与 B/C 新计划双向校验。该静态间隔不是“运行完成”的保证：浏览器共享锁和每次执行的状态闸门仍是最终保护，耗时超过间隔时应以失败闭锁并人工核查。
