# 日报多机器人路由设计（第一阶段：配置模型，未启用单店发送）

## 现状与问题

当前 `wecom_message_routes` 以 `message_code` 为唯一键，一类日报只能绑定一个机器人。收银日报的图片和发送日志都是全门店汇总口径。仅在前端加“门店选择”无法保证每个机器人只收到自己门店的数据。

## 页面结构

| 唯一入口 | 职责 |
| --- | --- |
| 企业设置 → 机器人登记 | Webhook 凭证、机器人名称、启停及归属。门店机器人必须绑定唯一门店；管理群机器人标记为管理群。此处不发送日报。 |
| 日报管理 → 日报任务 | 每种日报一个任务：管理群汇总、门店单店日报、团购日报等。显示受众、启用状态、计划和最近发送结果。 |
| 日报任务 → 接收范围 | 表格按门店列出绑定机器人、状态、最近发送日期。一个机器人不能被误绑定到其他门店。保存绑定不会发送或自动开启计划。 |
| 日报任务 → 预览与发送 | 选择日期与接收对象。管理群预览汇总图；门店群预览仅含该店数据。确认后才允许测试或人工发送。 |
| 日报任务 → 自动计划与记录 | 设置该类日报的发送时间；逐门店显示成功、跳过、失败、结果未知。采集计划继续留在数据导入。 |

## 数据与发送契约

1. 机器人登记和日报绑定分开存储。绑定至少包含 `report_code`、`audience`、`store_id`、`bot_id`、启用状态和版本号；管理群绑定的 `store_id` 为空，门店群绑定必须有门店。
2. 单店日报生成器只接收一个 `store_id`，输出中不得含其他门店的名称、金额、排名或汇总。后台再次校验“绑定门店 = 报表门店 = 发送目标门店”，不能只靠前端筛选。
3. 每个接收对象独立记录发送状态，以业务日期、日报类型和门店为防重键。发送前先持久化占位；网络结果未知时停在待核对状态，不自动重试。一个门店失败不把其他门店已成功发送的记录重放。
4. 当日没有收银数据或全零时，门店任务记为“无数据跳过”，不发送空日报；已有部分数据但校验失败时记为“数据异常”，待人工核查。
5. 新门店绑定默认关闭。历史上的全店汇总路由和计划原样保留；不得按机器人名称猜测门店或自动批量启用。

## 落地顺序

本轮已确定先完成布局与配置模型，暂不发送单店日报。机器人注册表增加用途和唯一归属门店；日报管理增加门店群机器人配置概览。现有管理群汇总仍使用原来的发送路由与计划，且全店汇总只能绑定管理群机器人。门店机器人登记不会开启任何发送。

下一阶段再实现独立的日报任务绑定、单店预览与隔离测试、逐接收对象发送与防重、计划和结果记录。云端发布前逐项核对现网源码与数据；不覆盖业务数据库。
