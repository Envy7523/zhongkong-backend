## 三、事实二：行尾（CRLF/LF）造成的 diff 假象

### 3.1 实测数据

| 位置 | 行尾 |
|---|---|
| git 对象库（`git show HEAD:server.js`） | **LF**（CRLF 行数 = 0） |
| release 工作区文件（含本次上传的） | **CRLF**（如 `server.js` 7141/7141 行均为 CRLF） |
| `core.autocrlf` | 未设置 |
| `.gitattributes` | 仅 `assets/fonts/*.ttf filter=lfs ... -text`，未约束 JS/Vue 行尾 |

### 3.2 同一批文件，两种算法

| 命令 | 结果 |
|---|---|
| `git diff --stat` | 26 files changed, **17052 insertions(+), 16632 deletions(-)** |
| `git diff --ignore-cr-at-eol --stat` | 26 files changed, **616 insertions(+), 196 deletions(-)** |

逐文件对照（真实差异，忽略行尾后）：

| 文件 | 真实差异 | `git diff` 原始显示 |
|---|---|---|
| `server.js` | 114 行 | 14,174 行 |
| `lib/business-analytics.js` | 16 行 | 10,384 行 |
| `lib/db.js` | 64 行 | 4,436 行 |
| `lib/sync-job-audit.js` | 18 行 | 974 行 |
| `lib/schedule-routes.js` | 34 行 | 750 行 |
| `frontend/src/views/analysis/SyncRuns.vue` | 50 行 | 684 行 |
| `frontend/src/views/analysis/MonthlyOperatingDashboard.vue` | 154 行 | 154 行（该文件本就是 LF，所以数字一致） |
| 其余 14 个文件 | 各 3–64 行 | 同量级放大 |

### 3.3 影响判定

- **功能影响：无**。Node 与 vite 均正常处理 CRLF；本轮部署 `node --check` 7/7 通过、
  前端构建 4.57 s 成功、服务 `active`、公网 32 个资源全 200。
- **工程影响：有**。任何一次 `git commit` 都会把 1.7 万行白噪音写进历史，掩盖真实改动。
- **归属判定：非本次引入**。release 工作区在我 09-30 12:40 首次同步**之前**就是 CRLF；
  本地对应文件同日 15:32–17:02 也已是 CRLF。仓库既无 `core.autocrlf`、
  也无覆盖 `*.js` 的 `.gitattributes`，因此"工作区 CRLF / 库内 LF"是长期存在的结构性差异。
