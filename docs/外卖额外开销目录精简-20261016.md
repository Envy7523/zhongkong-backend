# 外卖额外开销目录精简（本地完成，未上云）

用户要求删除外卖字段分类中多余的额外开销字段。

问题：目录读取真实历史类型后，又为各平台预置“霸王餐、推广充值、推广充值（第三方费用）”。实际录入接口只接受“霸王餐、第三方推广”，因此美团、淘宝出现4行；京东无历史记录时也出现3行。

处理：`lib/delivery-fee-rules.js` 改为只预置实际可录入的“霸王餐、第三方推广”，已有同名记录不再补行。移除两个没有真实记录的推广充值占位项，不删除数据库记录、不迁移或覆盖已保存人工分类、不改变金额和费用计算规则。若历史库确有其他名称的真实记录，仍按原名称显示，以免丢失历史记录的分类入口。

本地与云端只读查询确认，当前真实额外开销只存在“霸王餐、第三方推广”。此次仅改本地代码并重启本地测试后端；云端未修改。

验证：`node --test tests/delivery-fee-manual-rules.test.cjs tests/store-finance-revenue.test.cjs`，18项通过。覆盖各平台仅两项预置、已有类型不重复、无记录旧占位项消失、真实历史名称/分类/记录保留、读取不写配置、原费用计算与防重口径。

本地运行接口前后证据：`_tmp/personnel-ui-polish-20261016/fee-catalog-before.json`、`fee-catalog-after.json`。前端入口 `/analysis/delivery/fee-rules`，刷新或点击“重新读取”加载新目录。
