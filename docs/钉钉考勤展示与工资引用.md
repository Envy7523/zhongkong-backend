# 钉钉考勤展示与工资引用

2026-10-07：员工周排班入口更名为员工考勤。排班在钉钉维护，此处仅展示计划、实际分段打卡和库存查询；周排班及异常编辑接口在生产模式拒绝写入，原有历史排班、异常记录仍保留。

现有钉钉应用已实测具备考勤组查询权限。通过 schedule/listbyusers 获取工作日、休息标记、计划班次与审批关联，独立存入 dingtalk_schedule_days。实际打卡继续沿用原同步。计划时间不参与实际工时计算。

首次自动同步覆盖上月1日至今天后14天；之后每6小时回扫最近7天并覆盖未来14天。可以点击同步本周获取所选门店/办公室的历史或未来周。权限实时校验，店长只能查看、同步本店归属人员；支援人员仍按既有归属及支援登记核算。没有钉钉绑定者展示未获取。

一次同步先获取全部范围数据，再原子更新，每人每日唯一。空返回写入未获取状态，避免已删除班次残留；失败保留原成功快照。重复绑定 userid、范围外数据、异常结构会拒绝。日志不输出凭证。操作人默认已绑定人员的首个 userid（实测可读取）；可通过 DINGTALK_SCHEDULE_OPERATOR_ID 显式配置经授权的操作人。

工资表制作提供引用钉钉考勤按钮，先预览再确认带入草稿。正式员工引用实际计薪天数并沿用存假规则，兼职引用配对实际工时与既有时薪；不按计划班次付工资。仅已结束月份、月份应出勤设置已提交且整月考勤完整的员工可带入。跨店支援、集团发薪展示行及待核人员保留工资原值。已提交/已审核工资不可覆盖，来源快照或工资版本变化会拒绝旧预览写入。

当前接口中的 approve_id 只是审批引用，不足以确定请假或调休类型、时长、批准/撤销状态；此类日期明确待核，不虚构请假或扣库存。休息与出勤混合节点、未获取班次、班次缺段也待核；考勤窗保持只读。后续需读取审批详情并核对撤回状态，才能覆盖这些异常人员的自动工资引用。

库存不追溯产生启用日期之前的存假；历史月份的工资核对可以引用已同步的正常考勤。旧人工计划不再作为新的考勤来源。所有原始计划快照保留在同步表，工资引用记录进入原工资审计流程。现有审核流程及工资标准、代扣代缴权限不变。

验证包含：真实权限和分段班次读取、休息标记、只读接口、门店隔离、同步删除/幂等/失败回滚、工资预览来源变化拒绝、实际工资及兼职工时金额核算。
