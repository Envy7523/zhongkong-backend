# 门店档案与筹建资料协作重构方案

日期：2026-11-02。状态：方案，未修改业务代码、权限、资料字段、设备绑定或线上页面，未建立新消息发送或设备采集计划。

## 目标与现有基础

围绕同一门店 ID，串联门店日常资料、筹建资料、设备及视频通道。门店名称由公司维护，名称变化不重新建店或改变关联 ID。设备部分等待用户提供接入文档、设备清单和样例，当前不更新页面、不生成模拟数据。

普通更名沿用原 ID；迁址、闭店重开遵循现有门店生命周期规则，新旧门店分别关联和记账，不为方便采集而合并历史。

已核对现有代码：stores 有 phone、business_hours、lat、lng、address；网页 StoreBasic 有这些维护入口；现有岗位/人员具有门店范围、店长身份及督导关系，已有通知、协作和操作日志。当前通用门店更新接口可以修改店名、状态等，不能直接把整套 store.manage 授给店长。当前 API 接入登记可复用连接登记与受控密钥管理，但不等于已有厂家设备适配能力。

沿用[智能水电表与门店监控接入架构方案](智能水电表与门店监控接入架构方案-20261028.md)的设备契约、单位/时间/质量规则、总分表去重、视频受限授权和独立存储原则。该旧方案也仍是设计状态。

## 1. 门店资料自助维护

小程序入口：我的门店→门店资料。店长只维护其有效任职门店；兼任店长和督导使用已授权门店选择器，不另建人员归属体系。

| 资料 | 建议维护方式 |
| --- | --- |
| 门店联系电话、营业时间、门店联系说明 | 店长本店修改后生效并留痕；督导按授权范围维护 |
| 地图定位、详细地址 | 可提交修正；影响正式地址、区域归属或其他地理规则的变更由公司确认后生效 |
| 门店名称、内部编号、经营主体、正式开闭店状态、平台 ID、设备归属 | 公司维护；店长不能通过普通资料接口修改 |
| 证照、合同、收款等筹建资料 | 进入资料提交及审核流程，按资料类别控制访问，不能靠自助基本信息接口修改 |

营业时间支持多时段、跨午夜、休息日及临时调整；保存结构化值，同时兼容现有展示字段。地图记录坐标系及来源，选择营业点位；不把一次用户手机实时定位直接当作门店位置。不会因内部资料修改自动同步到美团、地图商户或其他外部平台。

营业时间带生效时间和历史版本，未来能耗规则使用事件发生时的营业时间，不能用今天的新时间重判旧告警。

后端提供独立字段白名单，校验门店范围、身份有效期、版本号；拒绝夹带店名、状态、法人等字段。读接口、更新、附件和导出均执行同样边界。修改记录包含操作者、时间、字段差异及必要原因，敏感内容脱敏；并发修改只合并明确无冲突的字段，有冲突展示差异，不整张覆盖。

## 2. 筹建档案与阶段验收

公司先创建状态为“筹建中”的门店档案，指定责任店长、督导、公司审核人。名称未定时由公司设置筹建编号占位，之后统一命名。保存资料不会自动变为正常营业，也不会纳入只针对营业门店的统计范围。

筹建负责人可以单独获得该筹建项目的资料权限，不要求先正式任命为营业门店店长；筹建项目成员不因此获得正式店长身份、人员工资或设备视频权限。负责人调换、离职或筹建结束时相应权限同步收回。

把原来一张表的必填规则拆成三种：

- 草稿保存：允许不齐全，先保存已取得的部分；未填写项保留未知。
- 本次补充提交：只校验本次填写/上传内容是否有效，不要求其余资料齐全；错误格式不能作为正式资料完成。
- 阶段验收：按公司确定的适用清单检查该阶段必须项；不齐全不能登记为该阶段完成。开业验收和日常补充分别处理。

资料项可配置“本阶段必须 / 后续必须 / 选填 / 不适用”；不适用须有理由，并由授权审核人确认。模板带版本，变更已执行清单时有补项记录，不静默改动原验收结论。首期仅做筹建专用模板，不扩展成全站低代码表单系统。

档案可展示：收集中、待阶段审核、需补充、阶段通过、筹建资料已验收。每项展示：未提供、草稿、已提交待核、退回补充、已确认、不适用。阶段进度和资料完整度分别计算；上传文件不等于审核完成。

例如适用清单 20 项，首次提交 5 项：显示已提交 5、待审核 5、待补充 15。后续店长、督导、受邀老板都补到同一档案；审核人退回两项，只退回两项，其余资料和进度保留。

每个缺项指定责任人、预计补齐时间、缺失原因；关键缺项自动成为现有工作台待办。站内提醒按门店汇总、去重，超期按约定升级给督导。提醒保持到资料确认或有明确延期处理；已读、延期与资料完成是不同状态。外部微信、钉钉、短信提醒仅在实际接通并配置授权后启用，本次不发送。

开业后尚允许补齐的资料继续追踪；证照更新/到期换证保留版本和审核过程，不能拿新文件覆盖旧的验收依据。

## 3. 无后台账号的老板协助提交

采用受邀的 H5 手机填报页；微信中可打开链接，手机浏览器也可使用。无需后台账号，但并非公开匿名入口。微信小程序登录可作为后续身份方式，不能默认要求老板已加入企业微信。

流程：内部负责人选门店及缺项→生成限定邀请→自行转发老板→受邀者验证身份并阅读填报用途告知→分次保存/上传→提交本次补充→公司审核。

邀请绑定单一筹建档案、资料项范围、邀请人、接收者、有效期和访问上限，可撤销重发。接收者可采用指定手机号验证码验证；若尚未配置短信能力，使用内部确认接收人的流程和独立访问码，明确安全强度差别，不把单独持有链接认作已核验老板身份。敏感资料首期应使用已核验接收人的邀请方式。

临时访问身份仅可填写被邀请的资料项、查看/继续自己的提交，不能访问后台、其他门店、设备、监控、员工、工资或已有敏感资料。邀请权限上限由公司模板决定，不能超过邀请人的授权；如某项只允许财务接收，店长发起补资料请求不因此获得读取财务附件的权限。

老板填的内容先进入待审核提交区，不直接覆盖正式档案；外部身份及邀请人都记入提交记录。文件有受控访问、类型/大小校验和版本，链接不永久公开。过期邀请失效，已提交草稿不随链接失效而删除，可由内部重新邀请同一接收者继续。

手机验证确认的是接收者对手机号的控制，老板身份及资料真实性仍由邀请人和公司审核确认。

资料用途与必要告知在收集时呈现；普通资料与敏感资料分别控制权限和必要同意，不通过上传行为冒充签约或签字。完成后显示提交回执与待补清单，负责人持续承担资料闭环责任。

## 4. 水表、电表及监控接入

关联链路：厂家租户/连接→外部设备/通道 ID→内部设备/计量点→带有效期的门店绑定。外部 ID 用字符串精确匹配，名称只辅助人工核对；同店可多表多通道，设备换店、换表、迁址保留旧绑定时间段。

管理员在一个设备接入入口维护厂家连接、凭据、待绑定设备、归属、计量与告警规则；业务页面只显示已授权门店的数据。台账名称/点位可维护，投运设备停用归档；原始读数、厂家事件和历史归属不提供普通行删除/覆盖。首期只读，不开放断电、关阀、清除录像等控制动作。

后端负责凭据、厂家适配、回调验签或限流增量采集、去重、断点补采及运行审计。页面查询本地已同步数据并显示来源时间；不在每次打开页面时扫描全公司设备。密钥不发到网页或小程序。

水电原始点位数据使用独立采集任务和独立存储，业务库只保留关联及必要摘要；避免当前 SQL.js 整库持久化承载高频读数。累计值差分识别换表/归零/缺采，零与缺数据分开；总分表不重复加总。费用标估算并与实际账单对照，不重复写成本。

监控使用厂家受限实时/回放能力，点击播放才申请短时指定通道授权，离开释放；视频不写入业务 SQLite，不默认让当前业务服务器转存所有录像。接收厂家实际支持的告警后关联现有通知/协作。实时、回放、事件及小程序播放能力分别按文档和实机核验，未知能力不能宣称已支持。

未来页面建议：门店档案内展示水电摘要/监控入口；门店运营中复用水电和监控业务页；设备接入管理只在管理员专区。不新增三套门店菜单。水电页显示本日/本月用量、趋势、最后测量/同步时间、异常；监控页按门店/点位展示实时、回放和事件。未接入、待绑定、无上报、离线、零用量分别表示；本轮不改实际界面或展示伪数据。

## 5. 权限总表

| 身份 | 基本资料 | 筹建资料 | 水电/监控 | 公司配置 |
| --- | --- | --- | --- | --- |
| 公司管理员/授权负责人 | 授权范围维护；公司指定名称 | 清单、分工、审核、阶段验收 | 按现有管理权限及专项视频授权 | 设备接入及绑定仅管理员 |
| 店长 | 有效任职门店的指定字段 | 本店分次提交、跟进缺项、受控邀请 | 本店能耗；视频单独授权 | 无 |
| 督导 | 授权门店指定字段 | 所管门店提交与督办；审核另授 | 所管门店能耗；视频单独授权 | 无 |
| 外部老板/受邀协助者 | 仅邀请允许的资料项 | 单档案指定缺项、自己的提交 | 无 | 无 |

现有超级管理员通配权限要按当前机制准确描述；若要求管理员也不能看视频，需独立调整超级权限，不能靠隐藏入口承诺隔离。新增接口默认拒绝未登记权限；分别校验渠道、功能、门店、字段、资料敏感程度和设备/视频动作。

## 实施顺序与待确认内容

1. 门店资料自助维护：字段白名单、店长/督导门店范围、定位变更确认、修改日志。
2. 筹建档案：模板及阶段、分次保存、逐项审核、缺项分工、工作台提醒。
3. 外部邀请：限定资料项、接收人验证、跨日续填、私有附件和公司审核。先一店试用再扩展。
4. 设备文档到位后：核对厂家租户/编号、单位/时间/倍率、采样周期、分页补采、事件、实时/回放授权及额度；一店试点后扩店。当前不更新设备前端或启用采集。

实施前由业务确定各阶段的资料清单与验收人、哪些资料允许外部提交、接收人验证方式；厂家文档和一店样例到位后再确定设备契约与交付范围。对外账号、主密钥不作为普通聊天附件或填报资料收集。
