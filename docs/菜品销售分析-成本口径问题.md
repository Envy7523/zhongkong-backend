## 1. 用户发现的现象

同一个菜品「招牌烧鹅饭」，两层看到的预估成本不一样：

| 位置 | 销量 | 收入 | 预估成本 |
|---|---|---|---|
| 上层（跨 5 个平台合并那一行） | 327 | ¥8,438.00 | **¥4,414.50** |
| 展开后明细表「合计」行 | 327 | ¥8,438.00 | **¥4,419.00** |

销量、销售额、收入都能对上，**只有成本差 ¥4.50**。

线上整月数据重现同一规律（差异随量放大）：

```
招牌烧鹅饭（17,601 份）
  上层（跨平台合并）     237,613.50
  规格维度（常规）       237,614.00
  明细逐条四舍五入相加   237,619.00
```

**同一批钱，三个视图给出三个数。**

---

## 2. 根因

后端 `finish()` 里同一批明细行被算了**两遍，算法不同**：

| 数值 | 原算法 |
|---|---|
| 上层「预估成本」`estimated_cost` | 汇总后的**平均单价**（`total_cost / cost_weight`）× **汇总销量** |
| 明细每行「成本」`sources[].cost` | 每行**菜单单价 × 行销量**，各自 `round2` |
| 明细表「合计」行 | **前端**把上面那些已取整的行相加（`detailSubtotal()`） |

菜单成本单价带零头（实测有 12.38、3.69、52.15 等），**逐行取整后相加 ≠ 汇总后统一计算**，于是差出几块钱。

这不是浮点误差（差 4.5、7.0 这类整数级），而是"分层取整"的必然结果：
每一行取整引入最多 ±0.5 分，行数一多就累积成元级。

---

## 3. 已做的修复（本地，未上云）

改动文件：`lib/business-analytics.js` 的 `finish()`。

- 明细来源先各自 `round2`，然后 **上层成本 = 各来源行成本之和**（原来是先汇总再算）
- 没有来源行时退回规格明细之和，再退回原始累计值
- `net_income`、`total_cost` 用同一口径重算，避免毛利跟着漂

**验证（本地库，100 个菜品全量核对）：**

```
上层成本 vs 明细合计：已核对 100 个菜品，不一致 0 个  ✅
抽查「招牌烧鹅饭」：上层 194362 = 明细 12 条合计 194362  ✅
                    net_income 194118 = 收入 388480 − 成本 194362  ✅
```

**修复后效果**：明细表「合计」行与上层那一行的预估成本**分毫不差**（原来差的 ¥4.50 消失）。

## 4. 待敲定的残留问题

### 4.1 规格维度 vs 来源维度仍会差几元

`sku_breakdown`（按菜单 SKU/规格分组）与 `sources`（按 平台+原始菜名+规格 分组）是**同一批行的两种切法**，
各自逐条取整后仍不等：

```
太公烧鹅（10,265 份）：规格合计 535,324  vs 来源合计 535,331（差 7）
招牌烧鹅饭：            规格合计 194,360  vs 来源合计 194,362（差 2）
共 18/100 个菜品存在此差异
```

**这是"同一批钱按两种方式分组后分别取整"的数学必然结果**，无法同时让两种分组完美对齐。

**可选方案（请敲定）**

- **方案 A**：规格维度改为"按来源行反推"（规格成本 = 该规格下各来源行成本之和）。
  两个维度完全一致，代价是规格单价不再是"菜单单价 × 数量"，`unit_cost` 会带零头。
- **方案 B**：保持现状，在界面上标注"规格维度与来源维度各自取整，允许几分差异"。
- **方案 C**：全部改成不取整、显示时再格式化（改动面最大，会影响已对外的所有成本字段）。

当前实现是 **修复了主表对账（上层 vs 明细），规格维度维持原状**，即倾向方案 A 但未执行。

### 4.2 相关口径需要复核的地方

- `unit_cost` 现在 = 上层成本 ÷ 销量（取整后回算），带零头时与实际行单价可能差几分
- `cost_weight`、`cost_source`（`sku` / `dish_avg` / `none`）语义未变，但汇总口径变了
- 门店经营指标里的"预估毛利"走的是另一条链路（`cost_amount` / `spec_cost_sum`，见 `lib/business-analytics.js` 约 4015-4060 行），
  **本次未改动**，是否要与之统一口径需要一起判定
