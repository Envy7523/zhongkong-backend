日期：2026-11-02。范围：用户指定 open.ulucu.com，公开官方文档只读评估。未接收管理员密码，未登录企业账号，未申请或使用 AppSecret，未调用真实门店/设备接口、播放实际视频、注册推送或修改项目业务代码。

## 初步结论

与项目的门店监控、3D 点位联动方向匹配。官方公开文档有门店、NVR/IPC 通道、在线状态、新版实时播放、本地/云录像回放、告警查询和数据推送接口。网页集成可行性较高；用户企业是否实际开通相应接口、存储服务、权限范围、并发额度、费用及小程序支持仍待账号/厂商验证，不能据文档认定已接入成功。

## 项目关联方式

内部 store_id ↔ 悠络客门店 store_id → 设备 SN/设备内部 ID → 通道 → 模型版本及点位 ID。

管理员在独立接入/绑定页面核对一次门店及通道，业务页面只使用已确认的绑定。NVR 整机、通道、摄像头点位分别建模，防止把整台录像机当作单个摄像头。变更门店/设备归属保留生效时间及历史。

API 返回的是设备和视频关系，不能自动还原厨房、仓库的三维坐标和镜头朝向；这些需要在门店 GLB 模型中标点并校准，保存到模型版本。3D 点击摄像头点位后，先平滑聚焦并突出标记，再按用户动作打开该通道视频；点厨房区域不自动同时播放所有摄像头。

## 数据及播放设计

- 后台集中保存应用凭据和生成签名；同步可见门店、设备、通道、状态及告警元数据。
- 用户请求播放时，后端校验渠道、门店、通道、实时或回放权限，再申请播放地址并维护受控会话。
- 不能仅在中控隐藏其他门店按钮。需要验证厂商给客户端的临时播放凭据是否限制到指定设备/通道及期限，避免能修改 URL 跨店观看；文档未足够证明的隔离能力须专项验证。
- 优先让视频由厂商媒体服务向播放器传输，现有业务服务器负责鉴权、会话和必要元数据。若厂商的授权隔离或播放方式要求网关，再评估带宽和部署，不能先承诺所有视频都能安全直连。
- 本地回放增加通道占用、占用人提示、超时释放及必要排队。是否能共享同一时间段、实时与回放是否互相影响，以及停止推流的作用范围，交由厂商/实机确认，不直接执行全通道停止影响其他观看者。
- 使用普通只读视频能力先试点；云台、对讲、设备绑定/解绑、修改码率及远程控制不因有接口就一并开放。
- 告警先接入实际授权事件；推送与查询补漏结合，关联现有协作待办，不重复产生多条持续告警。注册回调是正式配置操作，本次未执行。

## 需要在企业账号或向厂商确认

1. 是否已有开放平台应用及 AppID/AppSecret；应用是否授权到用户现有企业门店，哪些接口实际开通。
2. 先选一家门店：NVR/IPC 型号、设备 SN、通道清单及一个有历史录像的通道。哪些设备只在本地存储、哪些有云录像。
3. 接口调用频率、直播/回放并发、流量/转码/云存费用、IP/域名限制、播放地址有效期及撤销方式。
4. 官方推荐网页播放器/接入样例，HLS/HTTP-FLV 及实际编码；微信小程序的正式接入方案和真机支持。
5. 告警查询/推送可用类型、设备离线与通道不可播放的区分、推送重试、补查时间范围及签名时间单位。

下一步可由用户自行在浏览器登录现有平台，只读查看应用权限、门店、设备及录像方式。管理员密码不写入普通聊天、源码或项目资料；生产应用凭据通过后台受控配置。取得正式应用授权后，再做“一店、一通道、一次实时、一次真实回放、一条告警”的实际链路试点。
