# 人员管理视觉优化（已上云）

2026-10-16已获授权并上云，当前版本、备份与线上验证见[发布记录](人员资料与外卖字段精简上云-20261016.md)。下文保留开发阶段过程与本地验证。

用户反馈合并后的功能符合需求，但视觉不如合并前。本次沿用已确认的功能结构，恢复深蓝渐变页头、成员头像及卡片层次，优化人员目录、筛选区、岗位范围和详情抽屉。

## 范围

- `PersonnelAccess.vue`：一个新增入口；页头展示人员总数、已配置人数与微信待处理数；带可见标签的筛选区；成员头像与账号信息；主岗/兼任和范围分行；登录端、绑定与配置状态分层；账号资料分组；新增步骤与窄屏布局。
- `PersonnelRoleEditor.vue`：主岗位卡片与兼任卡片的视觉区分，改善字段间距与添加入口。
- `tools/personnel-management-fixture.js`：隔离预览加载真实全局样式、企业主题及中文 Element Plus 文案，以发现主题样式冲突。

初次视觉优化未调整业务接口、人员数据、正式店长唯一性、分端权限及岗位范围算法。后续个人资料迭代增加了下述手机号格式校验与头像裁剪；没有新增收集字段、第三方依赖或小程序改动。原有未提交文件继续保留，未恢复合并前的重复功能入口。

按用户截图反馈，人员目录去掉独立的“主岗 / 兼任”标签；主岗位名称直接以浅蓝背景呈现，兼任岗位保持普通文字。悬停说明和读屏文案保留岗位类型信息，岗位分配规则不变。

## 个人资料与头像裁剪

用户指出账号持有人主要是集团成员和店长，要求手机号语义明确、头像置顶并允许自定义裁剪。

- 资料顺序调整为头像、基本资料、已关联员工档案（如有）、微信与密码。未关联员工档案不再占用顶部提示区域。
- “账号联系方式”改为“手机号”，选填；非空时按项目现有员工格式要求填写11位中国大陆手机号，拒绝微信号、QQ号及不合法号码。前端字段提示与后端新旧资料接口统一检查，不改变历史已保存数据，不将格式合格视为号码归属验证。
- 新增 `AvatarCropDialog.vue` 和 `utils/avatar-crop.mjs`：PNG/JPEG/WebP原图最多10MB、4000万像素；本地缩放100%～400%、拖动/方向键移动、重置、重新选图及实时预览；生成512×512 PNG后调用现有头像保存接口（仍限制2MB）。取消不上传原图、不改原头像。
- 头像保存与资料保存分开；头像更新后保留姓名、手机号等未提交草稿。只有资料字段与打开时的基线一致，才同步头像变更后的资料版本，保留并发变更冲突保护。
- `lib/personnel-profile-fields.js` 复用手机号校验；`personnel-directory.js` 与 `server.js` 旧账号入口接入。人员岗位、门店范围及小程序代码未变。
- 隔离工具的头像接口只把图片存入内存，不使用正式头像目录。

验证：

- `node tools/personnel-management-smoke.js`：手机号拒绝/去空格/留空、资料隔离及头像变更后的旧版本拒绝，原人员管理检查继续通过。
- `node tools/avatar-crop-smoke.mjs`：横图/竖图居中、缩放、拖动边界、小图/大图和重复绘制稳定性通过。
