# 店长员工权限与工资审核

## 账号

管理员在「人员管理」创建账号，选择 **店长（员工与工资）** 岗位，并绑定门店。服务端根据当前账号绑定门店过滤员工和工资表；修改账号归属或岗位后立即生效，不依赖登录时缓存。

店长只开放本店员工基础信息录入、编辑和工资表制作。员工固定薪酬、调店、离职、照片附件及第三方同步仍由完整人事入口维护。新员工默认固定薪酬为 0，须由人事补齐薪酬后再生成工资表。历史工资表包含其他店支援员工时，店长入口拒绝打开，由人事处理跨店分摊。

原「门店店长」岗位保留，避免改变已维护的岗位权限；新账号请使用新的专用岗位。系统不自动创建或改绑实际账号。

## 应出勤

每个月有独立的 **集团员工**、**门店员工** 两项应出勤设置。集团范围为永文总公司、鹅太公连锁、鹅太公品牌、同盛；其余营业门店使用门店设置。两者均需由人事提交，数值为 1–31 天，支持小数。

升级将原月度统一设置复制到两项设置，保留原值，不推测两类员工应出勤的差异。没有旧月度设置的月份需人事先提交，才能生成新工资表。

设置更新只同步该月份、该人员类型的草稿、已保存和退回表，增加版本并留痕；待审核、已审核表保留提交时口径。退回后使用当前人事设置重新制作。普通员工行的应出勤和日工资分母读取同一工资表设置，支援行仍从 0 天起按支援天数分摊，修复历史明细 26 天与月度设置 25 天不一致的问题。

## 制作和审核

1. 人事提交当月集团、门店应出勤。
2. 店长生成或打开本店工资表，直接输入出勤、加班、奖罚、代扣数值，保存明细。
3. 「保存并提交审核」先保存当前明细，再锁定为待审核。版本冲突会拒绝提交，需重新打开。
4. 持有「工资审核」权限的人查看明细并通过或说明原因退回。提交人不能审核本人提交的工资表。
5. 已审核工资表锁定，普通保存与应出勤设置变更均不改动其明细；正式 Excel 只允许审核通过的表导出。其他状态可导出带「草稿 · 未审核」标题的预览。

工资编辑不覆盖员工固定薪酬档案。店长固定薪酬只读，完整人事可调整当月工资快照。员工身份、门店归属、自动分摊天数不能通过工资表请求替换。保存、提交、退回、通过与基线更新记录操作人、版本和明细快照。
