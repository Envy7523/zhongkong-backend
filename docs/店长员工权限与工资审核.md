# 店长员工权限与工资审核

## 账号

管理员在「人员管理」创建账号，选择 **店长（员工与工资）** 岗位，并绑定门店。服务端根据当前账号绑定门店过滤员工和工资表；修改账号归属或岗位后立即生效，不依赖登录时缓存。

店长只开放本店员工基础信息录入、编辑和工资表制作。员工固定薪酬、调店、离职、照片附件及第三方同步仍由完整人事入口维护。新员工默认固定薪酬为 0，须由人事补齐薪酬后再生成工资表。历史工资表包含其他店支援员工时，店长入口拒绝打开，由人事处理跨店分摊。

原「门店店长」岗位保留，避免改变已维护的岗位权限；新账号请使用新的专用岗位。系统不自动创建或改绑实际账号。

## 应出勤

「人事专区 → 月出勤管理」独立维护每个月的 **集团员工**、**门店员工** 两项安排。集团范围为永文总公司、鹅太公连锁、鹅太公品牌、同盛；其余营业门店使用门店设置。管理员和人事可查看历史、提前设置未来月份，其他岗位不能进入管理页面或调用历史清单接口。

每日安排包括工作、休息、放假、选填上下班时间及备注，支持次日下班和批量设置。提交时须覆盖当月每一天，应出勤天数自动统计工作日期。按北京时间判断可编辑月份：本月及未来允许编辑，上个月及之前在服务端锁定，管理员也不能绕过。旧月份只有天数时保留原值、每日明细显示未登记，不虚构日期。原「人事」岗位补充明确的月出勤权限，其余仅持有员工查看权限的岗位不会自动获得此权限。

升级将原月度统一设置复制到两项设置，保留原值，不推测两类员工应出勤的差异。没有旧月度设置的月份需人事先提交，才能生成新工资表；历史月份缺失设置时保持未登记，不解除历史锁定。出勤每次提交记录操作人、版本和日历快照。

设置更新只同步该月份、该人员类型的草稿、已保存和退回表，增加版本并留痕；待审核、已审核表保留提交时口径。退回后使用当前人事设置重新制作。普通员工行的应出勤和日工资分母读取同一工资表设置，支援行仍从 0 天起按支援天数分摊，修复历史明细 26 天与月度设置 25 天不一致的问题。

## 制作和审核

1. 人事提交当月集团、门店应出勤。
2. 店长生成或打开本店工资表，直接输入出勤、加班、奖罚、代扣数值，保存明细。
3. 「保存并提交审核」先保存当前明细，再锁定为待审核。版本冲突会拒绝提交，需重新打开。
4. 管理员或持有「工资审核」权限的人从独立的「人事专区 → 工资审核」打开已提交的待审核工资表，查看明细并通过或说明原因退回。制作页仅列草稿、已保存和退回记录，提交后从待处理列表移除。提交人不能审核本人提交的工资表。
5. 已审核工资表锁定，普通保存与应出勤设置变更均不改动其明细；正式 Excel 只允许审核通过的表导出。其他状态可导出带「草稿 · 未审核」标题的预览。

工资制作使用通用区域门店选择器；店长显示固定本店，不提供跨店选项。工资明细序号列显示「序号」，标准工资各项与统一工价均只读并带 ￥ 符号；管理员、人事也不能通过工资保存接口修改固定薪酬，应在人事薪酬档案维护。已有表保留生成时快照。员工身份、门店归属、自动分摊天数不能通过工资表请求替换。保存、提交、退回、通过与基线更新记录操作人、版本和明细快照。

审核页默认上个月，可按工资月份及门店、集团范围查看提交进度和应提交、已提交、未提交 / 待重提、待审核、已审核数量。应提交范围使用所选月份实际制薪员工（含当月入职、当月仍应计薪的离职人员和支援人员），或已有工资表的归属；无制薪员工的营业门店单独标明，不计入漏交。草稿、已保存和未制作均算未提交，退回算待重提；只有带有效提交时间、提交人的待审核或已审核表算已提交。

待审队列与已审核历史分为两个标签。提交进度显示提交人、提交时间，仅已提交记录提供审批明细入口。`/api/payroll-review/:period` 和明细接口只允许审核权限；独立审批明细拒绝草稿、已保存、退回及其他月份记录，管理员也不能绕过。仅有审核权限的账号使用旧明细、列表和预览导出接口也不能读取未提交表。审核明细只读，退回后移出审批区、恢复制作入口，重新提交后再次进入队列。

## 员工工资条查询

「人事专区 → 员工工资条查询」按月份和员工编号合并同月本店、支援门店的工资快照。同名员工不会合并；标准月工资不重复累加，只汇总各店实际承担的应发、代扣、实发金额，并展示计薪天数、支援日期、工资项目及门店承担明细。

默认查看已提交（含待审核），可切换仅已审核；有制作权限的人事、管理员可查看包含未提交的预览。店长仍只开放本店员工录入和工资制作，不能读取员工跨店工资；仅有审核权限的账号不能查询未提交明细。尚未生成工资的门店不会估算金额，工资表覆盖情况显示未生成员工明细、未提交、待审核、退回待重提或已审核，未纳入当前范围的门店提示汇总不完整。只有全部应纳入门店均已审核，才标记已审核汇总。既有工资表、员工与薪酬档案均不修改。
