# 美团团购「门店基础数据」导入失败 · 根因与修复留档

> 记录时间：2026-09-23
> 现象：上传 `9.15-9.22美团基础数据.xlsx` 报「未找到美团团购"门店基础数据"工作表」
> 结论：`lib/business-analytics.js` 里一个别名解析辅助函数漏改，导致该导入器**对任何文件都不可用**

---

## 1. 根因

`meituanGroupOperationSheet()`（识别函数）内部定义了一个只接受**字符串**的列定位辅助：

```js
const col = label => headers.findIndex(value => cleanKey(value) === cleanKey(label));
```

但同一个对象里按**别名数组**调用它，用来兼容新版导出的列名：

```js
gross: col(['成交金额', '成交金额(优惠后)']), income: col(['核销金额', '消费金额']),
```

`cleanKey` 的实现是：

```js
function cleanKey(value) {
  return String(value == null ? '' : value).trim().replace(/[\s_（）()]/g, '').toLowerCase();
}
```

数组经 `String()` 变成 `"成交金额,成交金额(优惠后)"`，与任何真实表头都不相等，于是这两列恒为 `-1`：

```
col(字符串) date            ->   0  "日期"
col(字符串) storeId         ->   1  "美团门店ID"
col(字符串) impressions     ->   3  "曝光人数"
col(字符串) visits          ->   4  "访问人数"
col(字符串) purchases       ->   6  "购买人数"
col(数组)   gross           ->  -1   ← 解析失败
col(数组)   income          ->  -1   ← 解析失败
判定所需列: [0,1,3,4,6,-1,-1]  → 识别失败
```

识别失败即抛出「未找到美团团购"门店基础数据"工作表」，**导入在识别阶段就结束，任何文件都进不来**。

### 为什么是回归，而不是一直如此

- 同文件另有三个 `col` 辅助：L1132 的 `col = labels => {...}` 与 L1794 的
  `col = aliases => header.findIndex(cell => aliasHit(cell, aliases))` **都按别名数组处理**，
  只有 L1997 这个漏了。
- 线上导入批次佐证：最后一次成功的「门店基础数据」导入是 **2026-09-15 12:45**（批次 91
  「中控台基础数据.xlsx」，09-01~09-14，308 行 = 14 天 × 22 店），此后无成功记录。
- 也就是说：为「支持新版列名」而把 `col('成交金额')` 改成 `col([...])` 的那次改动引入了本回归。

---

## 2. 修复

让 `col` 支持别名数组，按顺序逐个尝试（与文件内其余三处写法保持一致）：

```js
const col = label => {
  const aliases = Array.isArray(label) ? label : [label];
  for (const alias of aliases) {
    const index = headers.findIndex(value => cleanKey(value) === cleanKey(alias));
    if (index >= 0) return index;
  }
  return -1;
};
```

影响面：`meituanGroupOperationSheet` 仅被 `importMeituanGroupOperationWorkbook` 调用（L2024），
其余导入器不受影响。
